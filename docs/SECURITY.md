# الأمان والخصوصية

## حدود الثقة

كل ما يأتي من المتصفح أو أسماء المنتجات أو نص Gemini غير موثوق. حماية صفحة الإدارة وحدها لا تكفي؛ كل API وRPC وStorage policy تتحقق مستقلًا. RLS تمنع الوصول للصفوف غير المملوكة، وGRANT يحدد أصلًا ما يمكن الوصول إليه. [مرجع Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

## الجلسات والأدوار

تحقق من توقيع الجلسة بالطريقة الرسمية في إصدار Supabase المستخدم؛ لا تثق بـgetSession وحده على الخادم. اقرأ الدور من staff_roles لكل mutation إداري بدل user_metadata الذي قد يعدله المستخدم. تعطيل staff_roles.active يمنع العملية التالية حتى لو بقي JWT قديمًا. العمليات عالية الامتياز تتحقق أيضًا من صلاحية المستخدم الحالية؛ لا cache طويل للصلاحيات.

عملاء Supabase للجلسات منفصلون عن العميل السري. العميل السري لا يُستخدم كحل لتجاوز أخطاء RLS. bootstrap أول Manager إجراء محلي موثق لا endpoint عامًا. منع إزالة آخر مدير تحت قفل ومعاملة. كلمات مرور الديمو فريدة، لا حسابات admin/admin ولا credentials في Git. يوصى MFA للمدير قبل تشغيل متجر تجاري.

## سياسات البيانات

- profiles: المالك يعدل حقول الملف المسموح بها فقط؛ لا يرى قائمة العملاء.
- cart/favorites: user_id يطابق auth.uid في USING وWITH CHECK.
- orders/items/history: العميل يقرأ طلبه فقط؛ الإدخال والتعديل عبر خدمة الشراء والحالات.
- catalog: العام يقرأ DTO المنشور فقط؛ لا draft أو كمية مخزون أو بيانات تشغيل.
- inventory role: لا وصول إلى عناوين أو هواتف أو إجماليات مبيعات من views أو logs.
- quiz/results: ملكية الجلسة إلزامية؛ رابط UUID لا يمنح وصولًا.
- views: security_invoker عند انطباقه، ولا استخدام view تتجاوز RLS دون حدود مدروسة.
- SECURITY DEFINER: محصور في schema خاص، search_path ثابت فارغ، تحقق هوية/دور، revoke افتراضي ومنح التنفيذ بدقة. worker منفصل عن المستخدم.

## الأسرار

`GEMINI_API_KEY` و`TELEGRAM_BOT_TOKEN` و`SUPABASE_SECRET_KEY` و`CRON_SECRET` و`QUOTE_SIGNING_SECRET` و`RATE_LIMIT_SALT` على الخادم فقط. لا `NEXT_PUBLIC_` لها ولا طباعتها عند فشل validation. `.env.local` مستبعد من Git؛ `.env.example` بأسماء فارغة. دوّر أي سر تعرض بالخطأ وتحقق من إبطال القديم. API URL الخاص بـTelegram يحتوي token، لذلك يجب تنقيحه من سجلات HTTP.

## التهديدات وضوابطها

| التهديد | المنع والاختبار |
|---|---|
| تعديل السعر من المتصفح | تجاهل السعر وإعادة التسعير في DB، اختبار payload مزور |
| شراء آخر وحدة بالتزامن | أقفال وصفقة ذرية وفحص stock>=0 |
| استخدام كوبون أكثر من الحد | قفل coupon وعد uses تحت القفل |
| تكرار الطلب | idempotency per user + request hash + unique constraint |
| IDOR | اقرأ طلب عميل آخر أو نتيجة جلسة أخرى: 404 دون بيانات |
| CSRF | same-origin على mutations، cookies مناسبة، لا قبول GET للكتابة العامة |
| XSS | النصوص plain text، لا dangerouslySetInnerHTML، تطهير rich text إذا أضيف لاحقًا |
| رفع ملفات ضارة | نوع ومحتوى وحجم وأبعاد متحقق منها، لا SVG خام |
| Prompt injection | بيانات منفصلة وallowlist وschema وfallback؛ لا tools للـGemini |
| إغراق Gemini/checkout | rate limits موزعة وtimeouts وحدود payload وإنذار استهلاك |
| endpoint العامل المكشوف | Bearer secret ومقارنة آمنة وعدم تضمينه في client |
| رابط عودة خبيث | returnTo مسار داخلي مسموح فقط، لا URL خارجي |

اضبط Security headers الملائمة: CSP بقائمة المصادر المطلوبة فقط، منع framing، منع MIME sniffing، سياسة referrer محدودة. لا تعطل حماية لمجرد إنجاح مكتبة حركة. SQL parameters بلا concatenation. تجنب SSRF باعتماد ملفات Storage المعروفة بدل تنزيل روابط يقدمها المستخدم.

## الخصوصية

Gemini يستقبل تفضيلات ونوتات فقط، لا هاتف أو عنوان أو اسم العميل. Telegram افتراضيًا ملخص بلا تفاصيل شخصية كاملة؛ تفعيل التفاصيل يحتاج Manager وقناة خاصة للموظفين المخولين. لا توجد قناة عامة للطلبات. الحساب والنتائج no-store، والسجلات لا تحتوي answers أو address كاملين.

الديمو يستعمل أشخاصًا وعناوين خيالية. سياسة مبدئية للاحتفاظ: anonymous quiz 7 أيام، نتائج الحساب 90 يومًا، operational logs 30 يومًا، audit 180 يومًا. طلبات الديمو تبقى حتى إعادة التهيئة المقصودة؛ للمتجر الحقيقي تحدد مدة الطلبات وفق حاجة النشاط والقواعد المحلية قبل الإطلاق. طلب حذف الحساب يعالج بتنقيح PII أو فصل الملكية مع الحفاظ على السجلات المطلوبة؛ لا cascade أعمى يمحو التاريخ المالي.

## بوابة القبول

اختبر الصلاحيات باستخدام مفاتيح عامة وJWT كل دور، لا باستخدام service secret وحده. راجع bundle المتصفح بحثًا عن الأسرار، واختبر تغيّر الدور فورًا، وRLS وStorage مباشرة. فشل أي اختبار تسريب بيانات يمنع العرض العام حتى الإصلاح.

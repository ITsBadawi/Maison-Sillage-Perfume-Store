# التقنيات وسياسة الإصدارات

هذه اختيارات المشروع. الأرقام الدقيقة للحزم تُثبت عند إنشاء التطبيق بعد التحقق من توافقها؛ هذه الحزمة لا تحتوي package.json أو lockfile وهميًا.

| التقنية | الوظيفة | قرار التنفيذ |
|---|---|---|
| Next.js App Router | الصفحات والخادم وSEO | إصدار stable مدعوم وقت البدء؛ استعمال Server Components افتراضيًا |
| React + TypeScript | المكونات والأنواع | React المتوافق مع Next.js، strict mode للأنواع |
| Tailwind CSS | التصميم المتجاوب | إعداد رسمي متوافق مع الإصدار المختار وتوكنات CSS |
| shadcn/ui | عناصر النماذج والحوارات والجداول | إضافة المكونات المستخدمة فقط وتخصيصها |
| Motion (`motion/react`) | حركة الواجهة | المزود الوحيد للحركات؛ احترام reduced-motion |
| next-intl | الترجمة والمسارات | ar/en وملفات رسائل منفصلة |
| Supabase PostgreSQL | البيانات والمعاملات | migrations وRLS وRPC للعمليات الذرية |
| Supabase Auth + `@supabase/ssr` | الجلسة والبريد وكلمة المرور | عميل متصفح وعميل خادم منفصلان |
| Supabase Storage | صور المنتجات والهوية | قراءة صور منشورة، كتابة الموظف المخول |
| Gemini API + `@google/genai` | كتابة شرح النتيجة | server-only، structured output، model من البيئة |
| Telegram Bot API | إشعار الطلب | HTTP من عامل الخادم، بلا webhook وارد في النسخة الأولى |
| Vercel | نشر Next.js والعامل المجدول | تحقق من أهلية الخطة وتواتر cron قبل العرض |
| Zod | تحقق حدود البيانات | نموذج واحد مشترك بين العقد وخدمة الخادم حيث يناسب |
| React Hook Form | النماذج الإدارية المعقدة | عند الحاجة، لا يلزم لكل نموذج صغير |
| Vitest + Playwright | قواعد العمل واختبارات المتصفح المتصلة بقاعدة محلية | تغطية السلوك والرحلات الفعلية بدل تفاصيل تنفيذ المكونات |
| Playwright | سيناريوهات المتصفح | اللغتان والأدوار والشراء والتوصية |

### إصدارات M0 المثبتة

تم تثبيت الحزم التالية في 2 أكتوبر 2026: Node.js 24.18.0 في بيئة العمل (الحد الأدنى للمشروع 20.9.0)، Next.js 16.3.8، React 19.2.4، TypeScript 5.9.3، Tailwind CSS 4.1.17، وnext-intl 4.14.8. الإصدارات المثبتة كاملة في `package-lock.json`، ويُحدّث هذا السجل عند ترقية مدروسة.

## سياسة التثبيت

استخدم npm ومدير حزم واحدًا. سجل إصدارات Node والحزم الأساسية في هذا الملف عند M0، واضبط `engines` وملف القفل. استعمل `npm ci` في CI. لا تذكر نموذج Gemini ثابتًا اعتمادًا على محادثة قديمة؛ تأكد أن النموذج المختار متاح للحساب ويدعم المخرجات المنظمة عبر طلب حقيقي، ثم عيّن `GEMINI_MODEL`.

الوثائق الحالية لـNext.js تعرض App Router، وMotion توثق استيراد React من `motion/react`. التوثيق الحالي لـSupabase يميز عميل الخادم عن المتصفح ويستخدم `proxy.ts` في Next.js 16؛ إذا اختير إصدار آخر اتبع ملفه الصحيح. المراجع في [SOURCES](SOURCES.md).

## حزم لا نحتاجها الآن

لا Prisma لأن Supabase SQL وgenerated types وRPC تكفي، ولا Redux لسلة صغيرة، ولا GSAP لحركات يمكن تنفيذها بـMotion، ولا LangChain لمهمة شرح منظمة، ولا vector DB لمطابقة حسابية. لا تثبت حزمة فقط لأنها مشهورة.

## إعدادات البيئة

انظر [.env.example](../.env.example). متغيرات `NEXT_PUBLIC_*` مكشوفة للمتصفح؛ المسموح بها URL التطبيق وURL Supabase وpublishable key فقط. مفتاح Supabase السري محصور بالعمليات الموثوقة مثل عامل الإشعار وإنشاء حسابات الديمو وخدمة الجلسات المجهولة التي تثبت token الملكية أولًا. تعامل المستخدم المسجل العادي مع قاعدة البيانات يحمل JWT المستخدم، ولا يستبدله المفتاح السري.

الخدمة لا تحتاج إلى Gemini حتى لتحديد أفضل العطور؛ إذا لم يضبط المفتاح تعمل المطابقة مع شرح fallback واضح للمشرف. هذا مفيد أثناء التطوير، لكن إثبات التكامل الحي شرط اكتمال مرحلة Gemini.

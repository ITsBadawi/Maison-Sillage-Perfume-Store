# دليل تشغيل وعرض الديمو

هذا الديمو يستخدم قاعدة بيانات حقيقية مع أسماء ومنتجات خيالية. يظهر تنبيه واضح في بيئتي `local` و`demo` بأن الطلبات للعرض فقط ولا يوجد شحن فعلي. لا توجّه الزبائن الحقيقيين إلى بيئة الديمو.

## بيانات البداية المثبتة في `supabase/seed.sql`

- 24 عطرًا خياليًا، عدة أحجام وصور SVG محلية ونوتات وملفات تفضيل، باللغتين.
- ثلاث مناطق شحن تجريبية في seed؛ المنطقة غير النشطة لا تظهر في checkout. يستطيع Manager تغيير المناطق والرسوم من اللوحة.
- الكوبون `WELCOME10`: خصم 10% بشروط الحد الأدنى والسقف وعدد الاستخدامات المخزنة في قاعدة البيانات. أنشئ كوبونات أخرى من لوحة Manager عند الحاجة؛ لا تفترض وجود `DEMO10` أو `EXPIRED` مسبقًا.
- أسئلة مستشار العطر منشورة مع خيارات بالعربية والإنجليزية. يمكن لمدير المتجر استنساخ نسخة مسودة، تعديلها، ثم نشرها.
- حسابات الموظفين **ليست** في seed. ينشئها `npm run demo:staff` محليًا بكلمات مرور عشوائية في `demo-credentials.local.json` المستبعد من الأرشيف. أنشئ حساب عميل عبر التسجيل، واستخدم أسماء وعناوين خيالية فقط.
- إعداد Supabase المحلي يؤكد بريد العميل تلقائيًا لتسهيل العرض. اختُبر مسار تأكيد البريد الحقيقي عبر Mailpit بإعداد مؤقت منفصل، ويجب تفعيل التأكيد وSMTP صالح عند النشر لاحقًا.

## التحضير المحلي

1. شغّل Docker Desktop ثم `npx supabase start`، واضبط `.env.local` وفق [دليل الإعداد](DEPLOYMENT.md).
2. على قاعدة محلية قابلة للمسح فقط، نفّذ `npx supabase db reset --local`. بعد reset احذف ملف الاعتمادات المحلي القديم وأعد `npm run demo:staff`؛ لا تشارك كلمات المرور على الشاشة أمام الزبون.
3. شغّل `npm run dev`. افتح `/ar` وتأكد من ظهور 24 عطرًا في المتجر قبل أي اختبارات تغير البيانات.
4. إذا أردت عرض شرح Gemini أو وصول Telegram حيًا، اضبط مفاتيحهما على الخادم وقناة تجريبية خاصة وجربهما مسبقًا. عند غياب المفتاح، يظل المستشار قادرًا على التوصية بشرح بديل، ويظل الطلب محفوظًا في outbox دون ادعاء وصول رسالة.

### تفعيل الخدمتين محليًا حين تكون المفاتيح جاهزة

ضع `GEMINI_API_KEY` و`TELEGRAM_BOT_TOKEN` في `.env.local` داخل مجلد المشروع فقط، ثم أعد تشغيل `npm run dev`. لا تضع أيًا منهما تحت اسم يبدأ `NEXT_PUBLIC_`، ولا ترسلهما في محادثة أو ملف ZIP. أضف بوت Telegram إلى **قناة خاصة تجريبية** بامتياز نشر الرسائل. سجّل دخول Manager، وافتح إعدادات Telegram في لوحة الإدارة، وأدخل `chat_id` للقناة وفعّل الإرسال. استخدم اسم عميل وعنوانًا خياليين في كل اختبار.

جرّب المستشار بالعربية والإنجليزية وافحص أن المنتجات والنسب لا تتغير مع شرح Gemini. بعدها نفّذ طلب COD تجريبيًا وافحص وصول رقمه للقناة، ثم حالة outbox في صفحة الطلب الإدارية. إذا لم تصل رسالة، يبقى الطلب محفوظًا ويمكن مراجعة السبب وإعادة المحاولة. عامل `/api/notifications/telegram` يحتاج `CRON_SECRET` وجدولة مستقلة عند تشغيله تلقائيًا؛ محليًا يمكن التحقق من المحاولة المباشرة بعد الطلب، لكن لا تدّعِ اختبار الجدولة المنشورة. إن تركت `includeCustomerDetails` غير مفعّل، لا يرسل البوت تفاصيل الهاتف والعنوان.

## سيناريو عرض مختصر

1. افتح المتجر بالعربية على الهاتف، أظهر التنقل والصوت الاختياري، ثم بدّل للإنجليزية مع بقاء الصفحة نفسها.
2. ابحث وصفِّ العطور حسب العائلة والسعر والمناسبة؛ افتح صفحة منتج وانظر إلى النوتات والحجم والسعر والتوفر.
3. أكمل أسئلة المستشار. اعرض حتى ثلاثة عطور متوفرة ونسب المطابقة وشرحها. النسب من محرك المطابقة الداخلي، وGemini يصوغ النص فقط عند عمله.
4. أضف عطرًا للمفضلة والسلة، سجّل كعميل، وتأكد من انتقال سلة الزائر إلى الحساب.
5. اختر منطقة وعنوانًا خياليًا، استخدم `WELCOME10` عند انطباق شروطه، وأتم طلب الدفع عند الاستلام. أظهر رقم الطلب وسجله في الحساب.
6. افتح حساب Orders Manager لترى الطلب وتغيّر حالته؛ ثم حساب Product & Inventory Manager لتعدّل المخزون ومنتجًا، وتبيّن أنه لا يستطيع إدارة الطلبات.
7. افتح حساب Manager لعرض إدارة الكوبونات والشحن والموظفين والأسئلة واسم العلامة، مع عودة الاسم الجديد للواجهة العامة بعد الحفظ.

## قبل العرض المنشور

جهّز مشروع Supabase demo منفصلًا، مصادقة البريد وSMTP، Vercel، مفتاح Gemini، bot وقناة Telegram خاصة، ومهمة إعادة محاولة للإشعارات. شغّل فحصًا حيًا للتسجيل واستعادة كلمة المرور والطلب والرسالة والشرح بالعربية والإنجليزية. اضبط سياسة الخصوصية وبيانات التواصل للنشاط قبل أي استخدام تجاري فعلي. لا تستخدم ملف اعتمادات الموظفين المحلي على استضافة عامة.

## إعادة التهيئة وحدود الدليل

`db reset --local` يمحو قاعدة المشروع المحلية؛ لا تشغله على بيانات زبون أو بيئة منشورة. البيانات التي تضيفها اختبارات المتصفح تظل موجودة حتى reset، لذلك قد يتجاوز عدد المنتجات 24 أثناء التطوير. يستعيد reset الـseed الأصلي، ثم تُنشأ حسابات الموظفين من جديد. نتائج المحاكاة لـGemini وTelegram لا تثبت الاتصال بالخدمتين؛ وثّق نتيجة الاختبار الحي عند إعداد المفاتيح.
